# 📜 GAME CONSTITUTION
# Used Phone Shop Tycoon

Version: 1.0
Status: Active

---

# 1. Vision

Used Phone Shop Tycoon is a business management simulation game focused on buying, repairing, negotiating, and selling used smartphones.

The goal is not to simulate phone technology, but to simulate the experience of running a successful second-hand phone business.

Every system must support this vision.

---

# 2. Core Philosophy

This game follows five fundamental principles.

## 2.1 Core Loop First

No new feature may be added before the existing Core Loop is enjoyable.

Core Loop is always the highest priority.

---

## 2.2 Gameplay Before Graphics

Gameplay is always more important than visual effects.

Beautiful graphics cannot replace enjoyable gameplay.

---

## 2.3 Decision Matters

Every major action should require player decision.

Examples

- Buy or reject
- Negotiate
- Repair or sell as-is
- Set selling price
- Upgrade shop

The player should never feel like they are simply pressing buttons.

---

## 2.4 Data Driven

Game logic should rely on data instead of hard-coded values whenever possible.

Examples

- Phone database
- Customer personalities
- Furniture
- Economy
- Shop upgrades

---

## 2.5 Modular Design

Every major system should be developed independently.

Examples

- Customer System
- Negotiation System
- Repair System
- Inventory System
- Economy System
- Shop System

Modules should communicate through clear interfaces.

---

# 3. Project Goals

Primary Goal

Create the best used phone shop simulation game that is easy to play, rewarding, and expandable.

Secondary Goals

- Mobile Friendly
- Browser Friendly
- Long-term Expandability
- AI-assisted Development

---

# 4. Development Principles

Prototype first.

Validate.

Improve.

Repeat.

Never build large systems without testing.

---

# 5. Scope Control

Every new feature must answer the following questions.

Does it improve the Core Loop?

Does it improve player decisions?

Does it improve replayability?

If the answer is "No", reconsider adding the feature.

---

# 6. User Experience

The game should be

- Easy to understand
- Difficult to master
- Fast to play
- Relaxing
- Rewarding

---

# 7. Performance

Performance is a feature.

Avoid unnecessary effects that reduce frame rate.

Smooth gameplay is more important than visual complexity.

---

# 8. Art Direction

The art style should remain consistent throughout the project.

Future assets must follow the official Art Bible.

---

# 9. AI Development Policy

AI is a development assistant.

AI does not replace project direction.

The project owner is responsible for all final design decisions.

---

# 10. Repository Rules

The main branch should always remain stable.

Every major feature should be developed separately before merging.

Documentation should be updated together with significant system changes.

---

# 11. Long-term Roadmap

Prototype

↓

Foundation

↓

Core Systems

↓

Content Expansion

↓

Beta

↓

Release

---

# Final Principle

When in doubt,

choose simplicity over complexity,

gameplay over graphics,

and long-term maintainability over short-term convenience.
